# Oil And Gas Strategy Gameplay Design

Date: 2026-06-06

## Purpose

Create a playable oil and gas strategy game loop inspired by Civilization and Age of Empires without adding administrative business screens. The first implementation should focus on mechanics, data, and simple playable feedback. UI polish and animation come later.

The player competes against AI companies first, with the same rules prepared for human multiplayer later. The game is won by building a stronger oil company through land control, exploration, drilling, connected facilities, production, and cash generation.

## Design Goals

- Make the game understandable: research, buy land, assign workforce, acquire equipment, build objects, produce, earn cash.
- Keep categories clean: tech is capability, manpower is role capacity, equipment is assets, activities are map actions, objects are things on tiles.
- Make finding oil fun through staged clues, risk, reveal, and useful partial failures.
- Make competition visible through land races, route blocking, capacity races, market pressure, and AI rivals using the same rules.
- Keep the first build system-heavy and visually simple; defer detailed UI layout, animation, and art polish.

## Non-Goals For First Implementation

- No contract negotiation gameplay.
- No detailed permit workflow.
- No separate pipeline access or JV management screens.
- No combat system.
- No real-time multiplayer implementation in the first pass.
- No high-fidelity UI animation pass yet.

## Core Game Loop

The main loop is:

1. Buy land.
2. Survey and run seismic to reveal clues.
3. Build roads and well pads.
4. Drill wells and reveal results.
5. Complete successful wells.
6. Connect wells with pipeline routes.
7. Build and upgrade gathering centers and tank farms.
8. Sell connected production.
9. Use cash to expand, research, staff, and build.

The core dependency rule is:

`map action available = required tech + required manpower role + required equipment + owned land + cash`

## Player Resources

- Cash: primary spend and score resource.
- Research: accumulated per turn to unlock tech.
- Manpower capacity: limits how many role staff can be trained and assigned.
- Equipment capacity: owned assets that enable or improve actions.
- Production flow: oil/gas units generated by completed wells.
- Storage capacity: buffer from tank farms.
- Environmental pressure: penalty meter driven by expansion and mitigated by HSE systems.

## Technology Tree

Technology nodes unlock capabilities only. They do not represent land buying, permits, contracts, or business paperwork.

Initial tech families:

- Exploration: Field Geology, Basin Modeling, 2D Seismic, Seismic Processing.
- Logistics: Desert Logistics, Road Construction, Well Pad Construction.
- Drilling: Exploration Wells, Deep Drilling, Directional Drilling.
- Production: Well Completion, Surface Processing, Pipeline Engineering, Storage Systems.
- Environment: Environmental Monitoring, Waste Handling, Low-Impact Operations.
- Late Game: Field Development, Enhanced Recovery, Automation.

Each tech has:

- prerequisite tech ids
- research cost
- turn estimate at baseline research output
- unlocks
- optional boost condition from field actions

Example boost rules:

- Survey three blocks to boost Basin Modeling.
- Run two seismic lines to boost Seismic Processing.
- Drill a dry hole to boost Exploration Wells.
- Build three connected pipeline segments to boost Pipeline Engineering.

## Manpower Tree

Manpower nodes are role families and ranks, not activities.

Role families:

- Geoscience: Field Assistant, Geoscientist, Senior Geoscientist, Chief Geoscientist.
- Engineering: Field Engineer, Drilling Engineer, Senior Drilling Engineer, Engineering Manager.
- Operations: Field Worker, Equipment Operator, Rig Supervisor, Operations Superintendent.
- Facilities: Maintenance Tech, Plant Operator, Facilities Engineer, Asset Manager.
- HSE: Safety Officer, Environmental Specialist, HSE Lead, Sustainability Director.

Manpower nodes define:

- training cost
- training turns
- upkeep
- role capacity provided
- action bonuses

Activities such as survey, seismic, road building, drilling, and production are not manpower nodes. They are map actions that consume or require manpower roles.

## Equipment Tree

Equipment nodes are game-friendly assets and kits, not activities.

Equipment families:

- Transport: Pickup, Crew Truck, Heavy Hauler.
- Survey: Survey Kit, Seismic Kit, Drone Scan Kit.
- Construction: Dozer, Grader, Crane.
- Drilling: Small Rig, Land Rig, Directional Rig.
- Production: Wellhead Kit, Separator Kit, Compressor Kit.
- Pipeline: Pipe Stock, Pipe Crew Kit, Pump Station Kit.
- Safety/Utility: Water Truck, Fuel Bowser, Generator Set, HSE Response Unit.

Equipment nodes define:

- acquisition cost
- acquisition turns
- upkeep
- action unlocks or bonuses
- optional per-use material costs

Pipe Stock is a per-segment material cost, not a one-time "buy pipeline" object.

Map actions create or upgrade objects on tiles.

| Action | Input | Needs | Object Result |
| --- | --- | --- | --- |
| Buy Land | click block | cash | Owned Block |
| Survey Block | click owned tile | Field Geology, Geoscience, Survey Kit | Survey Marker |
| Run Seismic | drag or select line | 2D Seismic, Senior Geoscience, Seismic Kit | Seismic Line / Prospect Map |
| Build Road | draw route | Desert Logistics, Operations, Dozer/Grader | Road Segments |
| Build Well Pad | click prospect tile | Well Pad Construction, Operations, Grader | Well Pad |
| Drill Well | click well pad | Exploration Wells, Engineering, Operations, Rig | Well Object |

| Build Pipeline | select source tile, select target tile | Pipeline Engineering, Operations, Pipe Crew Kit, Pipe Stock | Connected Pipeline Segments |
| Build Gathering Center | click owned hub tile | Surface Processing, Facilities, Separator Kit, Crane | Gathering Center |
| Build Tank Farm | click owned tile | Storage Systems, Facilities, Tank/Storage kit, HSE support | Tank Farm |

| Environmental Response | click affected object/region | HSE manpower, HSE Response Unit | Mitigation Project |

## Pipeline Route Builder

Pipelines are tile networks.

Rules:

- Player selects a valid source tile and a valid target tile.
- Valid sources: Producing Well, Gathering Center, Processing Plant.
- Valid targets: Gathering Center, Processing Plant, Tank Farm, export edge.
- The game previews a route across valid tiles.
- Each segment must connect by tile edge to the previous segment.
- Terrain affects segment cost: flat desert is cheapest, dunes cost more, rocky tiles cost most.
- Rival-owned land blocks routes unless a future diplomacy/business layer is added.
- Route length determines turns.
- Pump stations extend range and increase throughput.

Pipeline result:

- The activity creates multiple Pipeline Segment objects.
- A route is only productive when it connects a producing source to a valid downstream facility or export edge.

## Facility Objects

Facilities are map objects with size, footprint, capacity, cost, turns, and upkeep.

Gathering Center sizes:

| Size | Footprint | Capacity | Cost | Turns |
| --- | --- | --- | --- | --- |
| Small | 1 tile | 40 flow/turn | $35M | 5 |
| Medium | 2 adjacent tiles | 90 flow/turn | $62M | 7 |
| Large | 2x2 hub | 180 flow/turn | $110M | 10 |

Tank Farm sizes:

| Size | Footprint | Capacity | Cost | Turns |
| --- | --- | --- | --- | --- |
| Small | 1 tile | 120 storage | $18M | 4 |
| Medium | 2 adjacent tiles | 280 storage | $36M | 6 |
| Large | 2x2 yard | 650 storage | $70M | 9 |

Capacity consequences:

- If gathering capacity is too low, connected wells are choked.
- If storage is too low during market/export disruption, production is wasted or wells are shut in.
- Oversized facilities create high upfront cost and upkeep.

## Oil Discovery Model

Oil discovery should be staged and suspenseful.

Discovery stages:

1. Hidden basin potential exists in the generated world.
2. Surface survey reveals clues: seep, structure, rock clue, weak clue, or nothing.
3. Seismic raises confidence: low, medium, high, or very high.
4. Drill preview shows chance, expected reward range, and cost.
5. Drilling resolves into dry hole, oil show, gas discovery, commercial oil, or giant field.

Dry holes are not useless:

- They reveal basin data.
- They boost related research.
- They can improve nearby prospect confidence.
- They can expose better follow-up targets.

Well objects store:

- result type
- flow potential
- reserve estimate
- decline rate
- completion state
- connected network state

## Economy And Revenue

Cash generation requires a connected production chain.

Complete chain:

`Producing Well -> Pipeline Route -> Gathering Center -> Tank Farm or Export Edge -> Sale`

Revenue formula:

`cash per turn = sold production * market price - staff upkeep - equipment upkeep - facility upkeep - environment tax/penalty`

Market behavior for first implementation:

- Market price can vary by event.
- Early production can be rewarded.
- Oversupply can lower prices.
- Tank storage reduces losses from export/market disruption.

## Competition Model

AI and human players use the same rule set.

Competition sources:

- Land race: buying high-potential blocks first.
- Information race: private survey and seismic results.
- Route race: rival land can force longer roads and pipelines.
- Capacity race: rivals who build gathering/tank capacity can monetize sooner.
- Market race: early producers earn money before price drops.
- Technology race: better tech improves odds, cost, and environmental resilience.
- Environmental pressure: reckless expansion creates penalties.
- Victory race: cash, production, reserves, or technology.

## AI Companies

First implementation should support AI companies with strategy profiles.

AI profiles:

- Explorer: buys wide land, surveys aggressively, drills many cheap wells.
- Infrastructure Builder: prioritizes roads, pipelines, gathering centers, tank farms.
- Tech Investor: researches and upgrades manpower/equipment before aggressive drilling.
- Fast Producer: turns small discoveries into cash quickly.

AI turn decision order:

1. Evaluate victory pressure and current bottleneck.
2. Buy or defend land near promising clues.
3. Choose research based on profile and bottleneck.
4. Assign manpower/equipment to highest-value action.
5. Build or upgrade network objects if production is constrained.
6. Drill when expected value beats cash risk threshold.

AI must not receive hidden advantages except optional difficulty tuning that is visible to the player.

## Turn Structure

Solo first implementation:

1. Player planning phase.
2. Player action queue confirmation.
3. AI planning phase.
4. Resolution phase.
5. Reveal phase.
6. Score/economy update.

Future multiplayer:

- Simultaneous planning.
- Shared resolution.
- Same rules and object model.

## Victory Objectives

Supported victory tracks:

- Economic Victory: reach target company value or highest cash score after final turn.
- Production Victory: sustain target flow per turn.
- Reserve Victory: discover the largest proven reserve base.
- Technology Victory: complete late-game recovery and automation first.

For the first build, Economic Victory should be primary. Other victory tracks can be visible score tracks.

## Implementation Architecture

The web client currently uses React, Vite, and Phaser. The first implementation should add mechanics in data-oriented modules before UI polish.

Recommended modules under `Game/client/beep-oil-gas-sim-web/src`:

- `gameplay/types.ts`: shared ids and model types.
- `gameplay/balancing.ts`: costs, turns, capacities, prices.
- `gameplay/techTree.ts`: tech definitions and unlock checks.
- `gameplay/manpowerTree.ts`: role definitions, training, upkeep.
- `gameplay/equipmentTree.ts`: equipment definitions, acquisition, upkeep.
- `gameplay/actions.ts`: action definitions, validation, cost calculation.
- `gameplay/objects.ts`: map object definitions and state transitions.
- `gameplay/pipelineRouting.ts`: route validation, segment cost, connectivity.
- `gameplay/discovery.ts`: clue generation, prospect confidence, drilling resolution.
- `gameplay/economy.ts`: production flow, bottlenecks, revenue calculation.
- `gameplay/ai.ts`: AI profile decisions.
- `gameplay/turnEngine.ts`: action queues, turn resolution, reveal events.

Map rendering in `components/map/BasinMapCanvas.tsx` should consume game state but not own core rules.

React panels should display available actions, selected object details, queues, and turn results. Detailed UI and animation are deferred until the mechanics are playable.

## Testing Strategy

Unit tests:

- tech prerequisite and unlock checks
- manpower and equipment availability checks
- action validation
- pipeline route validation and segment costing
- discovery probability and deterministic seeded outcomes
- gathering/tank capacity bottlenecks
- revenue calculation
- AI action selection for each profile
- turn resolution order

Integration tests:

- land-to-producing-well chain
- producing-well-to-cash connected network
- dry-hole-still-rewards-data behavior
- AI competitor can buy land, drill, connect, and earn cash

Browser checks after implementation:

- start solo game
- select tile and buy land
- queue survey/seismic
- drill and see reveal result
- build pipeline route tile by tile
- build gathering center and tank farm
- end turns until cash is generated

## Implementation Order

1. Add gameplay types and balancing data.
2. Add tech, manpower, and equipment definitions.
3. Add object model and action validation.
4. Add discovery and drilling resolution.
5. Add pipeline route and connectivity logic.
6. Add economy and capacity bottlenecks.
7. Add turn engine.
8. Add simple AI profiles.
9. Wire the existing map and panels to the new gameplay state.
10. Add tests and browser verification.

## Open Scope Decisions

- First implementation should use AI opponents, not online human multiplayer.
- UI and animation are intentionally deferred until the mechanical loop is playable.
- Costs and capacities are game-balance values and can be tuned after playtesting.
